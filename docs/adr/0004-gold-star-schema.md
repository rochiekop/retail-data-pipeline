# Gold is a star schema

Gold is modelled as a star: one fact table at Order Item grain (`fact_order_items`) surrounded by denormalised dimensions (`dim_product`, `dim_date`, and later `dim_customer` and `dim_seller`). Product Category is folded into `dim_product` instead of being its own `dim_category` table, which would make it a snowflake. A snowflake saves a little storage and keeps category data in one place. A star needs fewer joins, and joins are the expensive operation in ClickHouse, while repeated category names compress to almost nothing in a columnar store. Analysts, dashboards and ML features also find a star easier to query. Report tables such as daily Revenue by Product Category are views over the star, so they always use the current catalog, matching the decision to overwrite catalog changes rather than keep history.
